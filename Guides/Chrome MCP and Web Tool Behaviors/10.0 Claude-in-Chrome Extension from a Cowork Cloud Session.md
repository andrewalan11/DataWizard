# 10.0 Claude-in-Chrome Extension from a Cowork Cloud Session

**Per-site permission is a hard gate, and it clears mid-session.** `navigate` to a domain the operator has not allowed in the extension fails at once with "Navigation to this domain is not allowed" (the batch stops there). Ask the operator to allow the site in the extension, then retry the same navigate - two sites that failed early in a session worked on retry after approval, with no reconnect needed. Some stay blocked; move on rather than looping. (Source: Kosmos, 2026-09) A screenshot can be refused on its own: right after a `navigate`, `computer screenshot` answered "Permission denied for this action on this domain" while `get_page_text` on the same tab worked. A site-permission prompt may be waiting in the extension; ask the operator to check it, and read the page as text meanwhile. (Events Map, 2026-10)

**The extension can go "not connected" minutes after it worked.** In one session the extension answered normally, then reported "not connected" about five minutes later, and two retries failed. Stop after two failures. Check `list_connected_browsers` (see 9.0). If the browser is gone, try the built-in browser (section 9.0) before handing that step to the operator; if that is also down, hand the step over and carry on with other work. (DataWizard, 2026-10; Rootland, 2026-10)

**`javascript_tool` results can be blocked wholesale.** On a site whose DOM values look like cookies or query strings (astro.com's `<select>` option values), every `javascript_tool` call returns `[BLOCKED: Cookie/query string data]`, even when the expression only reads option text. Use `find` / `read_page` on the element instead. The same block replaces any result that holds a URL with a query string (seen in two sessions): return ids or paths without query strings and rebuild the links outside the browser. (Source: Kosmos, 2026-09; LocationScout, 2026-10) Plain text can trip it too: business names with an `&` next to `=`-like text blocked a whole result. Replacing `[&=?%]` with spaces before returning let it through. (LocationScout, 2026-10; seen once)

**Some sites are refused by the extension itself.** `navigate` to reddit.com answered "This site is not allowed due to safety restrictions" at once. `old.reddit.com` was refused the same way (Tech Tools, 2026-10). This is a different message from the per-site permission gate above, and the session did not test whether allowing the site changes it. Hand the step to the operator instead: a short script they paste into the console of their own logged-in tab, which saves its result as a file (see section 6.0, the Reddit bullet). (DataWizard, 2026-10)

**A bot-check wall (Anubis) can clear after a short wait.** A GitLab site behind Anubis showed "Making sure you're not a bot" on first load. Navigating to the URL again and waiting about 5 s gave the real page, and `find` read the file list. `web_fetch` and sub-agents could not read it. Try the browser once more before you report such a page unreadable. (Community Stack, 2026-10)

**`javascript_tool` gives up at 45 s, but the async work keeps running in the page.** The call fails with "CDP Runtime.evaluate timed out" while the page code goes on. Start long work as a fire-and-forget async function that writes its result into a `window` variable, return at once, then poll with short calls (a `computer` wait of 10 s between polls). (LocationScout, 2026-10) A hung in-page `fetch` can also break the next calls: on a site whose data API had answered 403 to both shells, a `fetch` from its own tab hung until that timeout, the next call could not find the tab, and `tabs_context_mcp` timed out once before the extension answered again. Do not retry the same fetch in that tab. (LocationScout, 2026-10)

**Custom dropdowns populate the accessibility tree only after being opened.** `read_page` on a closed custom select shows one generic child; click it open, then `find "option items inside the X dropdown"` lists every option with its text - reliable for harvesting long option trees (74 options across 10 dropdowns in one pass). (Source: Kosmos, 2026-09)

**`computer screenshot` with `save_to_disk` writes into the cloud container**, at `/tmp/claude-chrome-screenshots-*/screenshot-<ts>-<n>.jpg`, not onto the operator's machine. Copy them with Bash and commit to the vault with `device_commit_files` from `/mnt/user-data/outputs/`. Sub-agents in the same session can open the files in place with Read (two reviewers worked from them). (Source: Kosmos, 2026-09; Rootland, 2026-10) In a Claude Code cloud session every Chrome screenshot is also saved under `/tmp/claude-tool-results/<id>/` in the container (the tool result names the path) and is lost when the session ends. To keep them, copy them to `/mnt/user-data/outputs/` and commit them with `device_commit_files`; 19 screenshots (1.2 MB) went into a project folder in one call. (Mesocosm, 2026-11)

**`browser_batch` stops at a site change.** After a `navigate`, a batch may hold page actions (screenshot, `get_page_text`, click) only while the navigate stays on the batch's first site (scheme, host and port). A batch with two navigates to different sites and page actions after the second is refused whole: "nothing in this browser_batch ran". Use one batch per site, and start the next batch with the navigate (it needs a `tabId`). (Mesocosm, 2026-11)

**A scroll can be a navigation on a zoomable web app.** On a board-style app, a `scroll` action over a tile zoomed into the tile and created a new step; it spent credits and changed the user's session. On canvas or zoom-style apps, read with `get_page_text` or `read_page` first, and scroll only over plain text areas. (Mesocosm, 2026-11)

**Page data has no path to a file except through the conversation.** `get_page_text` output up to about 52 KB came back inline in the tool result and was never saved to a tool-results file, as large MCP reads are. So ~50 KB of map data could only be read into context, and it could not be written to disk without typing it out again. Plan browser-only data pulls so the result is small (counts, ids, short lists), or send bulk data through a tool that writes files (the device shell, staging). (LocationScout, 2026-10)

**Chrome's built-in PDF viewer does not render in screenshots** - the main pane captures blank or black while the thumbnail rail is visible. A PDF you need to see must be fetched some other way (operator download, `fetch_pdf_from_url`); zooming the thumbnails is too low-res to read. (Source: Kosmos, 2026-09)

**`chrome-extension://` URLs are refused outright** - `navigate` answers "Can't interact with browser-internal or unparseable URLs", so an extension's own pages (OneTab's saves list, an extension options page) are unreachable in ANY connected Chromium browser (Chrome, Brave). Data living inside an extension gets out via the extension's own export (OneTab: Export URLs / the saved-tabs HTML export - the export was verified complete against the page's own link count), or by reading its LevelDB from disk with folder access. (DataWizard, 2026-09) The same "unparseable URLs" refusal came from `javascript_tool` on an ordinary site's page that was opened from a hand-built deep URL; the site's own links carry session tokens that the hand-built one lacked. Open inner pages by following the site's link from its home page. (LocationScout, 2026-10; seen once)

**The extension refuses `file://` URLs.** A local HTML page could not be opened that way. Serve the file from a local HTTP server, or ask the operator to open it. (Rootland, 2026-10)

**Headless Playwright in the cloud container cannot replace the extension for third-party sites.** The container's egress allowlist admits package registries and GitHub but resets connections to most product sites, so "screenshot it with Playwright" fails where the extension succeeds. Use Playwright only for local files (e.g. rendering your own artifact once before publishing). (Source: Kosmos, 2026-09)
