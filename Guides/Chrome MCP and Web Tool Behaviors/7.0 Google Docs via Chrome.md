# 7.0 Google Docs via Chrome

**Heading keyboard shortcuts type literal characters on Mac.** Ctrl+Alt+N and similar heading shortcuts do not apply styles through the Chrome tools -- they insert literal characters into the document. Use the style dropdown, or write plain text with caps. (Source: RW S17)

**Typed numbers auto-convert into nested lists.** When the cursor is inside existing list-formatted content, typing numbered text auto-nests it, and Ctrl+Z does not reliably revert large typed blocks. Workaround: paste the block via clipboard rather than typing it. (Source: RW S16)

**The Drive connector reads every tab of a Google Doc but cannot edit a Doc or add a tab.** `read_file_content` returns each tab under `# <tab name>`. To add tabs and formatted text, drive the Doc with Claude in Chrome: open the tabs sidebar ("Show tabs & outlines"), click "Add tab"; rename a tab by double-clicking its name, `cmd+a`, typing the new name, Return. Check the result by reading the Doc again with `read_file_content`: the new tabs appear under their names. (Common Woods, 2026-10)

**Paste formatted text with a synthetic paste event; no clipboard access is needed.** Convert the markdown to HTML, build a `DataTransfer` holding `text/html` and `text/plain`, and dispatch `new ClipboardEvent('paste', {clipboardData: dt})` on the `[contenteditable=true]` element inside `.docs-texteventtarget-iframe`. H2 headings, bullet and numbered lists and bold all survived. The element name is Google's, not a promise: probe it on the page before you rely on it. This is also the way around the typed-numbers nesting problem above. (Common Woods, 2026-10)
