# 7.0 Google Docs via Chrome

*Despite the title, this section also covers the Google Docs connector (`read_doc` / `update_doc`), which edits a Doc without Chrome.*

**Heading keyboard shortcuts type literal characters on Mac.** Ctrl+Alt+N and similar heading shortcuts do not apply styles through the Chrome tools -- they insert literal characters into the document. Use the style dropdown, or write plain text with caps. (Source: RW S17)

**Typed numbers auto-convert into nested lists.** When the cursor is inside existing list-formatted content, typing numbered text auto-nests it, and Ctrl+Z does not reliably revert large typed blocks. Workaround: paste the block via clipboard rather than typing it. (Source: RW S16)

**The Drive connector alone reads every tab of a Google Doc but cannot edit a Doc or add a tab (the Google Docs connector can - next item).** `read_file_content` returns each tab under `# <tab name>`. To add tabs and formatted text, drive the Doc with Claude in Chrome: open the tabs sidebar ("Show tabs & outlines"), click "Add tab"; rename a tab by double-clicking its name, `cmd+a`, typing the new name, Return. Check the result by reading the Doc again with `read_file_content`: the new tabs appear under their names. (Common Woods, 2026-10) A new Doc is the exception: `create_file` with `text/html` made a well-formatted new Doc; only changes to an existing Doc need Chrome or a paste by the operator. (Common Woods, 2026-10)

**The Google Docs connector edits an existing Doc in place, tabs included.** Its tools `read_doc` and `update_doc` can load deferred (load them with ToolSearch). `addDocumentTab` works although the `update_doc` description does not list it; the reply holds the new `tabId`, and every insert location and range in that tab then needs the `tabId`. With this connector on, no Chrome steps (above) or synthetic paste (below) and no operator paste are needed. (Common Woods, 2026-11)

**`read_doc` returns every tab, so a tabbed Doc is a large file on every read.** Results ran 400-700 KB, and one Doc grew from about 450 KB to about 4.4 MB after four tabs with tables were added. The result is always saved to a file and there is no per-tab read; parse it with python or the google-workspace skill's `docs_index.py outline` / `find` (`outline` worked on the inner `content` object). Each guarded write needs a fresh `revisionId`, so every write costs one large read. (Common Woods, 2026-11; ReWoven, 2026-11)

**A new table's multi-line cells work; bullets need a second pass.** With the google-workspace skill's `docs_index.py new-table`, a newline in a cell's text becomes a separate paragraph in that cell and the index arithmetic stays right. Add the bullets (`createParagraphBullets` per cell range) and bold on each cell's first paragraph in a second batch after a fresh read; never type bullet characters. (ReWoven, 2026-11)

**One-page check for one tab: export the whole Doc to PDF and find the tab's pages.** The Drive PDF export renders every tab in order, with a blank page between some tabs, so find the tab's pages by their text (`pdftotext -f N -l N`) and look only at those page images. To fit a two-column table on one page, fixed column widths gained the most (`updateTableColumnProperties` with `FIXED_WIDTH`; even widths made every item wrap), then 10 pt text and 3 pt cell padding. (ReWoven, 2026-11)

**Paste formatted text with a synthetic paste event; no clipboard access is needed.** Convert the markdown to HTML, build a `DataTransfer` holding `text/html` and `text/plain`, and dispatch `new ClipboardEvent('paste', {clipboardData: dt})` on the `[contenteditable=true]` element inside `.docs-texteventtarget-iframe`. H2 headings, bullet and numbered lists and bold all survived. The element name is Google's, not a promise: probe it on the page before you rely on it. This is also the way around the typed-numbers nesting problem above. (Common Woods, 2026-10)
