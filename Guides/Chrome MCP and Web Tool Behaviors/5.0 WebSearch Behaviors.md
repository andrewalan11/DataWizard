# 5.0 WebSearch Behaviors

**The search budget is about 200 calls per user turn, shared by the lead and every sub-agent, and it resets with the next user message.** Parallel research agents can exhaust it in one turn, and the last agent to run dry reports gaps. Give each sub-agent an explicit search budget and item target, run gap-filling in the next turn, and never downgrade an earlier sourced item to unconfirmed just because search ran out later - only a contradicting source does that. (LocationScout, 2026-10)

**When WebFetch fails on a Q&A site, the search snippets can carry the answer.** WebFetch failed on gutefrage.net with `client_error`, but WebSearch result snippets held the answer text, later comments included. Quote from the snippet and mark it as reported (read in a snippet, page not opened). (LocationScout, 2026-10)

**Small local topics: when helpers come back thin, the lead runs one narrow search per clue before widening.** Four regional research sub-agents (40-50 tool calls each) found almost nothing in local news for a small German and Austrian place topic, and a regional wiki was unreachable (`client_error` on one host, robots on the other). The lead found the key sources (a municipality history page, a regional news site) with one extended-mode search on a narrow phrase built from a single clue (an `opening_hours` tag in OpenStreetMap led to the local phrase for bottling spring water). (LocationScout, 2026-10)
