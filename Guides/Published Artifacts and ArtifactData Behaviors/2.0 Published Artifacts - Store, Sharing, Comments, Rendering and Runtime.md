## ArtifactData store

**`list` with `out_dir` writes bodies only; versions live in the result text.** Large documents move as files both ways: `set` / `update` take `file_path` (a local JSON file), and `get` / `list` / `query` take `out_dir` (each document saved as `<out_dir>/<collection>/<doc_id>.json`); a 166 KB document round-tripped byte-identical, so large artifact data can enter a vault workflow without retyping. The files hold document bodies; versions appear only in the tool's result text, so a run that must pin writes captures them from there. A `~` in a document id is spelled `@` in the file name (map it back). Past 50 documents the result folds the rest into one text line (`[N more saved documents ... "<id>" <v>, ...]`), so a parser that reads only the per-line form sees a fraction of the collection; an empty collection prints `No documents matched` and makes no folder. (Holonic Canvas, Evolutionary Media Commons, 2026-10)

**A whole-store export needs `out_dir`; the claude.ai chat database tools cannot do it.** The claude.ai chat surface reads an artifact's database with `db_list` / `db_get`, which return every document inline into the conversation, with no `out_dir` and no file output. Two documents of a change log came to about 15,000 tokens. A store of about 3,000 documents (7 MB) cannot be exported that way, and a model that retypes documents into files does not make a byte-exact copy. Run a whole-store export in a Cowork desktop session, where `ArtifactData list` with `out_dir` saves each document straight to disk; hand it a short brief. `db_usage` (document count and bytes) works from chat and is a cheap size check first. (DataWizard, 2026-11)

**Pinned writes are all-or-nothing.** A `batch` with any pinned entry is atomic: one stale pin returns `version_mismatch` naming the entry and its current version, and nothing is written. A pinned whole-document `set` (`if_version`) on a stale pin is refused the same way and lands on the current one. (Holonic Canvas, 2026-10)

**`update` merges nested objects; drop a key with the `__delete__` marker; keep bodies under ~850,000 bytes.** A key present in the store and absent from the body survives an `update`. `{"field": {"__delete__": true}}` removes it (proven live; the read-back carries neither the key nor a marker). Bodies near 1 MiB are refused - plan batches under ~850,000 bytes. (Holonic Canvas, 2026-10)

**Two-filter `query`, pinned `update` and republish survival are verified.** `query` with two `where` filters plus `order_by` works; `update` pinned with `if_version` works; the store's data survives a republish of the page. (Evolutionary Media Commons, 2026-10)

**Move shared state between two artifacts in one atomic `batch`.** Read the source page's documents (here `stars` and `data/users/me/prefs`), then write them to the new page under new keys in one `batch` (17 star documents and 1 prefs document). `collection: "data/users/me"` resolves inside a batch entry. The user id is the same across one owner's artifacts, so `by` copies as-is; keep the original `at`. After the move the two pages no longer sync - tell the operator. (LocationScout, 2026-10)

## Access and sharing

**Only the owner and Editors invited by email can write to an artifact `db`.** A Contributor, a Viewer or a public-link visitor reads only, and switching to a public link removes an outside Editor's write access - so a page that keeps shared state should tell the owner to invite collaborators by email as Editor, not share by link. `data/users/<id>/...` is private per person (good for per-person settings). (LocationScout, 2026-10)

**Admin-only root rules leave the owner's ArtifactData writes unrestricted.** Under root rules `read: admin, write: admin` the owner's ArtifactData writes are unrestricted while `as_level: interact` and `view` see nothing. (Evolutionary Media Commons, 2026-10)

**`as_level` gives a cheap post-publish check of the db rules.** With rules `<collection>` read view / write owner and `<collection>/{self}` write interact, an `ArtifactData set` at `as_level: "interact"` on another person's document failed with `invalid_argument: no such artifact, collection, or document (or no access)` and wrote nothing. That is the refusal shape, and it proves a Contributor cannot write another person's data. (MetaMyth, 2026-10)

**The publish result's sharing line is the live sharing state; do not assume more than it says.** After a republish it read "readable by only you" while the operator believed two collaborators were Editors. Before telling the operator that collaborators can open a new feature, ask them to check the Share menu. (MetaMyth, 2026-10; seen once)

## Comments from the operator

**Comment mode works as a feedback channel into a remote session.** When the operator comments on an artifact and uses "Send to Claude", each comment arrives in the session as a turn (with thread id and anchor), even though `ArtifactComments watch` reports "not supported yet from remote sessions". `read` lists threads with anchors (CSS path plus location label), `reply` posts as Claude labelled "via the user", `resolve` closes. Plain comments (not sent to Claude) do not arrive, so the operator says "check comments". Seven threads were built, answered and resolved in one round this way. (Evolutionary Media Commons, 2026-10; ReWoven, 2026-10)

**Read every open sent-to-Claude thread before acting on one.** Two comments on one paragraph arrived as separate threads ("remove" on the first sentence, "larger font" on the rest); acting on the first alone removed the whole paragraph, and the second thread showed the intent. Read every open thread on the artifact first, then act. (Evolutionary Media Commons, 2026-10)

**Comments not sent to Claude can be read but not answered.** `read` lists them as "not activated"; `reply` and `resolve` refuse. The session can read and apply them but reports in chat, and the threads stay open until a person resolves them in the artifact view. (ReWoven, 2026-10)

**The comment list gets expensive on a long-lived review artifact.** After about 90 threads, each `read` page is size-capped (about 14 threads) and lists threads sent to Claude first, so new un-sent comments sit several pages down. Resolved threads stay listed, and threads cannot be deleted. Page through with a fast-tier sub-agent that returns only the open threads after a timestamp (8 calls, about 135k sub-agent tokens, a short list back to the lead). Better: start a fresh review artifact for each review round and keep the old one for history. The same answer fits an operator's ask to "delete the comment history": Claude cannot delete threads, so publish the next version as a new artifact and record the old one as superseded. (ReWoven, 2026-10)

**The platform's comment panel is the speech-bubble button left of Share in the artifact frame ("All comments").** An empty panel ("No comments yet") matched `ArtifactComments read` ("No comment threads"), so the store was empty, not hidden. (MetaMyth, 2026-10; seen once)

**One artifact has two link forms, and a comment sent to Claude arrives with the uuid one.** The same artifact opens as `claude.ai/artifact/<short id>` and as `claude.ai/code/artifact/<uuid>`. A comment sent to Claude carries the uuid form, and `reply` and `resolve` work with it. (MetaMyth, 2026-10; seen once)

## Rendering constraints

**The artifact CSP blocks images from any outside host, so tiled web maps go grey.** Scripts load from a few CDNs (cdnjs works), but OSM, CARTO or Esri tiles never load and show no error. The fix that worked: embed a vector basemap (an Overpass extract simplified to ~400 KB) and draw it with Leaflet on a canvas renderer with no tile layer, Leaflet CSS inlined. This extends the general CSP rule in **Cowork Build Environment** (Device Bridge: "Chat-delivered HTML previews run NO page scripts; published claude.ai artifacts run scripts but block external hosts"). (LocationScout, Rootland, 2026-10)

**A published page opened in the claude.ai side panel at about 780-900 px wide and 500-560 px tall.** A check at 1600x900 can look right and still miss what breaks in the panel. Test a page with fixed-size parts (a 16:9 slide deck, a fixed stage) at 860x560 and 780x500 as well as full size. (ReWoven, 2026-10; seen once)

**Type sizes with a pixel minimum stop shrinking in a small panel, and the text runs over what sits below it.** In a slide deck, type set with `max(15px, ...)` stopped scaling below a stage width of about 970 px. What fixed it: a small fit script that steps a slide's type and gap scale down (to 66% at most) when its content does not fit, runs again on slide change, resize and font load, and lets the slide scroll as the last resort. (ReWoven, 2026-10; seen once)

**Browser automation cannot act inside a published artifact's frame.** The page runs in a nested cross-origin frame; Claude in Chrome and the built-in browser pane cannot click, type, read or run script inside it. The store read-back is the only automatable evidence of what a page wrote - in-memory page state has to be read by the person or shown on the page. (Holonic Canvas, 2026-10)

**An `obsidian://` link on a published page does nothing inside the Claude desktop app.** The app's frame blocks the custom scheme. The same link works when the artifact URL is open in a normal web browser, and pasting the copied link into the browser's address bar also opens Obsidian. Keep the direct link, add a "Copy obsidian link" button as a fallback, and tell the user to open the page in a browser. (Tech Tools, 2026-11)

**Nothing in an artifact link reaches the page, so a published page has no deep links.** The page runs in a frame on its own host whose URL carries no query or fragment: opened at `https://claude.ai/artifact/<id>?x=1#y=2`, a probe page saw empty `location.search`, `location.hash` and `document.referrer`, and the host's `postMessage` traffic to the frame carried theme, viewport and capability settings but no route. No runtime capability offers a link channel either (checked against runtime contract 0.2.75). A `#route=` scheme in a published page can never be hit from a link: route through a channel the page owns (a paste field, a `db` document another page writes, a sync), and probe with a scratch page that prints what it sees before building any routing. (Holonic Canvas, 2026-10)

**A prototype embedded in a page runs in `<iframe sandbox="allow-scripts" srcdoc=...>`.** Prototypes that load a library from cdn.jsdelivr.net or use `DecompressionStream` ran with no console errors; `allow-same-origin` was not needed. Once focus is inside the frame, Escape does not reach the parent page, so give the panel a visible Close button. (Kosmosis, 2026-10)

## Page runtime calls

**A second HTML page may not get the runtime; put capability code on the entry page.** The runtime contract names only the entry page; whether a second HTML page in `files` gets `window.claude` was not tested. Put capability code on the entry page and route other views by hash; keep a second page as a redirect. (MetaMyth, 2026-10)

**`sample` takes a size, not a model.** A page calls `sample(input, {modelTier})` with `quick`, `default` or `complex`. A named model (`model: "claude-..."`) is allowed only when the user names one, and the call falls back to the tier when that model cannot be used; `modelApplied` in the result says what ran. (MetaMyth, 2026-10)

**A `sample` call is paid by the viewer who clicks, not by the owner.** Pattern that worked: a size picker for the viewer (default Quick, remembered in browser storage inside try/catch), a cost warning beside the button, and no call at all when there is nothing to send. (MetaMyth, 2026-10; seen once)

**A published page can start a scheduled task, and only the task's owner can.** A page that declares `mcp: {servers: [{server: "Claude Code Remote", tools: ["fire_trigger"]}]}` can call `callTool("Claude Code Remote", "fire_trigger", {trigger_id})`. The call runs as the viewer, so only the owner of the task can start it: show the button only when `user.isOwner()` is true (`use("user")` itself can resolve `null`; treat that as not the owner). Keep the trigger id in a store document, not in the page source. What the started run can reach is in **Cowork Scheduled Tasks**. (MetaMyth, 2026-10; seen once)

**Count every live subscription before checking the cap.** The `db` cap is 64 active subscriptions per view, that is per open page, and the 65th rejects `resource_exhausted` (runtime contract 0.2.85). One page checked its count before its reply and thread listeners had started, so the check read 62 while the real total reached 79 with 40 people in the store. Count after all listeners are planned, then drop the optional ones if the total is over. (MetaMyth, 2026-10; seen once)

**A page that republishes itself sends one HTML document, so pages it carries must be inside it.** `artifact.publish(html)` sends only the document, not supporting files. To carry other pages (prototypes shown in an in-page viewer), embed each as base64 in a `<script type="text/plain" id="...">` and add those ids to the elements the page re-emits; each blob's sha256 was unchanged after a stubbed owner save. Put the blobs after the app script so first paint does not wait on them. (Kosmosis, 2026-10)

**A page cannot fetch other hosts; it can read files published with it.** A private page (contract 0.2.96, opened as the owner) that called `fetch()` on a public `raw.githubusercontent.com` file and on a `github.io` address got `TypeError: Failed to fetch` for both; a JSON file published beside `index.html` (publish_files) and read by relative path (`./data.json`) loaded with HTTP 200. The pages guide says the same: fetch, XMLHttpRequest and WebSocket to other hosts are blocked. No capability fetches an arbitrary URL. To give a page outside data, publish it as one of the page's own files (republish replaces it whole; db rows survive), or read it through the viewer's connectors with `mcp`. (DataWizard, 2026-11)

## Local testing and vault copies

**A local render needs the viewer's reset, or `hidden` sections stay laid out.** A page is published without its own head; the viewer adds a reset that includes `[hidden]{display:none!important}`. Rendered bare, a hidden tab's SVG stayed in the layout and intercepted test clicks. When wrapping a page for a local render or a vault copy, include the reset: `:root{color-scheme:light}body{margin:0}img{max-width:100%}[hidden]:not([hidden=until-found i]){display:none!important}`. The rule that a class setting `display` beats `hidden` in your own CSS is in **Browser and File System Access Behaviors**. (ReWoven, 2026-10)

**Or give the page its own reset for `hidden`.** Live, the wrapper's `!important` rule keeps a hidden panel hidden even when a class sets `display:grid` or `flex`; a bare local copy has no such rule, so the panel shows locally and not live. Add `#id[hidden]{display:none!important}` to the page's own CSS for each element toggled with `hidden`, and local and live behave the same. (Community Stack, 2026-10)

**Exercise `db` and `user` pages locally with a `window.claude` stand-in.** Load a small in-memory mock of `window.claude.use()` as a Playwright init script (Chromium launch: **Cowork Build Environment**, Verification Discipline for Builds) and drive the page before publishing. Keep the mock and a README beside the build. In one session it caught drop-target, undo and reorder bugs across eight publishes. A contract-faithful stand-in worked well with this design: inject it with `addInitScript`; resolve after the page's first script run, with a frozen namespace; fail loudly on methods the code does not use; keep the store in Node with `exposeBinding`, so reloads and a second page share it; support failure injection (null, `unavailable` once, `quota_exceeded`, `revoked`). (ReWoven, Evolutionary Media Commons, 2026-10)

**An artifact page saved to the vault as a standalone file is a fragment.** It has no `<!doctype html>`, `<html>`, `<head>` or `<body>` - the publisher adds them at publish time - so opened from disk it renders in quirks mode. Before shipping it as a standalone vault asset, prepend a document skeleton (doctype, `lang`, charset, viewport, plus the reset above) and wrap the body. (ReWoven, 2026-10)
