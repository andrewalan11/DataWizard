# 10.0 Scanning Third-Party Code

Behaviors of the scanners used to check repositories you do not control before you trust or run them.

- **GuardDog, OSV-Scanner and `sqlite3` are not installed in the device shell.** The device shell is a Linux VM and carries none of them (see the `sqlite3` bullet in [[8.0 Device Bridge]]), so a script that runs the scanners and writes their results into a database runs from the operator's Terminal on the Mac: hand over the exact commands, one for the scan and one to check it. For a one-off check without the Mac, the cloud container can install the pinned versions (see [[5.0 Network and GitHub Data]] and [[11.0 Claude Code Cloud Sessions]] for the downloads and hosts it needs). (VibeCut, 2026-10; Tech Tools, 2026-10)
- **OSV-Scanner call analysis runs the scanned repo's build code.** `--call-analysis=rust` executes the repo's `build.rs` (verified with a marker file), so for an untrusted repo always pass `--no-call-analysis=all`. A repo's own `osv-scanner.toml` can hide vulnerabilities unless `--config <empty file>` overrides it. `--no-resolve` cut a big repo's scan from 80 s+ to 11 s. (DataWizard, 2026-10)
- **OSV-Scanner can stop on one lockfile, and it counts every lockfile in a monorepo.** Version 2.7.0 failed on one npm `package-lock.json` with `cannot unmarshal string into ... peerDependenciesMeta`, and its error text printed a `src/` path prefix that the repository does not have, so do not search for that path. On a repository with demos and dev tooling it also counts each demo and dev lockfile: one UI-library monorepo showed over 200 advisories and none were in its published packages. Sort each hit into published package or dev tooling before you judge it. (VibeCut, 2026-10)
- **GuardDog 3.2.0 can report a clean run it did not finish.** A rule that throws on one file is skipped and the run still exits 0 (the failure shows under `errors` in its JSON output); it reads only a fixed, case-sensitive list of file types; and many rules stop at the first match. Installing it on a Mac with the newest Homebrew Python can fail to build - see the pipx bullet in [[3.0 Python and Packages]]. (DataWizard, 2026-10)
- **GuardDog 3.2.0 on a local folder runs the same 54 source rules whatever ecosystem subcommand you give, and it needs its Landlock kernel sandbox.** `pypi`, `npm`, `go`, `crates`, `rubygems` and `github_action` gave identical results on one repository, so one run covers every ecosystem. Each scan runs inside a Landlock sandbox by default and fails on a kernel without it, for any subcommand; `--no-sandbox` skips that protection. A scanning workflow that does not pass `--no-sandbox` reports an error on such a kernel and does not call the repository clean. (Tech Tools, 2026-10)
- **licensee 10.1.0 exits 1 with valid JSON when it finds no license.** `licensee detect <folder> --json` returns exit code 1 and a complete JSON body for a repository with no license file. Read exit 1 with parseable JSON as "none found", not as a tool failure. (Tech Tools, 2026-10)
- **A scanner's risk label says where to read, not what is wrong.** GuardDog 3.2.0 gave "high_risk" (7.9 and 8.2) and "suspicious" (5.9) to repositories whose hits were test strings, demo loaders, a dev bench, release tooling and an `osascript activate` call, and gitleaks "private-key" hits in one repository were dummy fixtures from a test-data generator. The concerns that mattered (a command-execution hook an agent can reach, a self-update by `git pull`, unrestricted local-path access by default, a token written to a shell profile, full-access agent settings forced on, an unpinned `npx -y ...@latest` skill line, provider keys in plaintext) were found only by reading the code. Read every flagged line first, then give the safety word from the read. (VibeCut, 2026-10; Tech Tools, 2026-10) The same holds for AI scan reports: treat each as a candidate finding that a person triages before a fix or a disclosure (in one vendor's early test, 85 of 97 reports met disclosure criteria, 11 repeated known issues and 1 was invalid). (DataWizard, 2026-10)
- **In a cloud session with a limited network, the scanners need extra hosts.** See [[11.0 Claude Code Cloud Sessions]] for the four domains, and for installing GuardDog with pipx. (DataWizard, 2026-10)
